# 浏览器认证跳转

应用按内网服务部署。`WEB_URL` 是内网基础地址，FRP 等转发层的地址不参与应用配置。

登录、退出及认证错误返回采用相对 `Location`；配置的 app/admin/space 基础地址只贡献挂载路径，不贡献浏览器跳转的主机。`next_path` 经现有校验后作为编码参数传递，保留嵌套查询且不能变成外站跳转。已拼好的站内目标统一移除 authority，保留路径、查询和 fragment。邮件链接及 OAuth 提供方回调需要绝对地址时仍使用自己的地址构造，不复用浏览器跳转函数。

不要通过识别内外网 IP、读取任意 Host 后重定向或维护外网入口名单解决站内跳转；浏览器从什么入口进入，就留在同一 origin。反向代理负责转发及正确传递请求头。

验证包括不同请求 Host 下的登录和退出、错误密码、恶意 next_path、带查询参数的返回目标；隔离副本中用真实浏览器填写表单，检查单次登录、刷新、退出和再次登录。发布后从真实内网入口重复验证。
