# 成果与应用

入口：部门工作区左侧「成果与应用」，路径 `/ai-strategy/gallery`。沿用现有工作区登录和项目权限，不新增端口或账号体系。

页面按业务场景展示应用、演示、文档和阶段成果。卡片可直接打开应用或预览交付材料；详情保留关联工作项入口，便于查看描述、评论与后续进展。成果数量按独立卡片计算，不按任务或附件数量计算；「含演示材料」表示收录了视频或演示链接，不代表外部平台权限已验证。

## 内容维护

`apps/api/plane/app/data/gallery.json` 只保存经过整理的标题、摘要、业务分类、来源工作项 ID、选中的附件资产 ID 和应用/演示入口。任务名称、项目名称、附件名称与大小从数据库实时读取，文件继续使用现有对象存储与预览服务。应用/演示地址必须仍存在于关联任务的链接、描述或未删除评论中，才会出现在页面。

更新内容时，先核对来源工作项，再选择能够证明成果的材料。任务完成不等于应用已上线；方案保留方案定位。不要填写未经记录的使用人数、节省时间或业务效果。新增卡片需要稳定且唯一的 key、至少一个有效来源，以及明确的主操作。更新配置后重新构建并发布 API 镜像即可；前端不需要为内容更新重新构建。

描述和评论中的 PNG/GIF 使用范围受限的同源预览入口：资产必须在清单内，仍属于对应的工作项，且工作区、项目、评论与资产均有效。普通附件沿用现有附件预览入口。超过 30 MiB 的 Office/PDF 材料提供下载，避免首次在线转换等待过长；其他材料是否能预览仍遵循现有格式支持。

初版有意不收录人事测评内容、未上传的工具分发包、可见文字与实际目标不一致的链接。原任务保留，不修改部门成员已填写的数据。

## 验证与发布

前端逻辑测试：`node --experimental-strip-types --test bokang/tests/gallery-ui.test.mjs`。后端数据库测试：使用隔离测试数据库，在 API 环境运行 `pytest -p plane.tests.conftest /path/to/bokang/tests/test_gallery_backend.py`。测试不得指向生产数据库。

运行镜像分别由 `bokang/Dockerfile.runtime` 与 `bokang/Dockerfile.gallery-api` 构建。API 镜像继承当前生产后端，保留既有模板、附件预览与层级筛选功能，无数据库结构变更。发布保留 Compose 备份和上一版镜像，以便回退。

上线验收需在真实登录状态下检查：来源任务跳转与返回、图片/视频/文档预览、下载与新窗口、详情与预览分别关闭、分类搜索、移动端滚动，以及非成员/跨工作区/不在清单内的资源拒绝访问。
