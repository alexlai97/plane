# 筛选与视图基础能力

已对齐目标：借鉴 Notion 的属性—操作符—值、条件组、分组和保存规则。任务业务数据不补造，视图规则能在界面创建、编辑、保存、刷新再读回。负责人、状态、标签的排除与空值、日期边界和动态日期是首要能力。

## 变更盘点

| 入口/数据                                     | 处理                                                 |
| --------------------------------------------- | ---------------------------------------------------- |
| 项目工作项、项目保存视图、模块、周期          | 共享筛选树和操作符；保持项目权限                     |
| 工作区视图、我的工作、个人档案、归档任务      | 沿用各入口已有字段可见范围，共享条件逻辑             |
| 工作项内子任务                                | 沿用已有字段范围；筛选和层级展开分开                 |
| IssueView / 用户布局 JSON / 模块周期布局 JSON | 保持现有字段，增加向后兼容多排序配置                 |
| Issue / 标签关系 / 负责人关系 / 模块周期关系  | 业务值不改；否定与空值以有效关系为准，忽略软删除关系 |
| ComplexFilterBackend / IssueFilterSet         | 统一验证、查询时相对日期、关系否定和空值             |
| 列表 / 看板                                   | 保留分组与泳道；升级多排序                           |

| 登录、模板、附件预览、成果展厅、管理员设置    | 不改授权和业务流程，发布后回归关键入口               |

## 时间语义

相对值保存为 today / previous_monday 等符号，在请求时按当前用户的系统时区解析。上一周一是上一日历周的周一，不是滚动七天。周报交集：start_date ≤ today AND target_date ≥ previous_monday；任一日期缺失不会满足这个交集。排除标签保留未打标签项，也排除同时含其他标签的任务。

## 数据迁移

管理命令 normalize_view_filters 默认预览，--apply 必须提供独占的备份文件。将极端日期范围转为单侧边界；只有显式选择的周报视图转相对边界。旧忽略分组的表格/时间线配置保持无分组，避免升级后突然改变展示。任务字段不改。后台 daily timer 停用后，用户改视图不再被脚本覆盖。

## 验收

后端隔离数据库测试：否定、多标签、软删除、空值、AND/OR、动态日期跨周、包含边界、日期空值、分组排序分页。前端：旧 NOT 配置读回、条件树编辑、保存刷新、布局切换、多排序、分组与父子项去重。生产对照真实任务集合；截图实际页面；共享视图成员范围保持一致。

## 操作约定与边界

- 标签筛选选“不属于”即可排除指定标签；未打标签的任务保留。排除应用于当前任务，不隐含排除全部后代。
- 条件组支持“全部条件 / 任一条件 / 不满足条件”，界面支持三级嵌套。切换布局沿用同一条件树，日历和时间线仍需日期才能定位。
- 展示设置支持多字段排序，列表前面的条件优先。删除全部条件回到手动顺序；分组按属性值，同一任务有多个负责人时会分别出现在各负责人的组内。
- 修改为当前浏览草稿；使用“更新共享视图 / 更新个人视图”后刷新仍保留，另存为创建独立视图。共享视图修改影响项目成员。
- 不识别的历史筛选保留并提示，保存由后端校验，不静默删条件。
